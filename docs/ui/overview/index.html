UI components

@consealdev/conseal/ui has the screens of the circle ceremony as Lit components, each a card in its own shadow root. They call only the CircleClient, with no crypto or HTTP of their own, and fire a DOM event when a step is done. Which screen comes next is the app’s to decide.

They are the places where the user sees a code and confirms that it matches, which a join needs on both devices before a key moves.

lit is an optional peer dependency: an app that doesn’t import /ui doesn’t need it. The components need a browser. Importing the entry point registers the elements:

Which screen, when

Section titled “Which screen, when”
The user is Show The element tells the app Then
Creating the circle on a first device <conseal-setup> setup-done, with the mnemonic <conseal-phrase>, until phrase-confirmed
Opening the app on a device the circle knows <conseal-unlock> unlock-done The app
Opening the app on a device the circle doesn’t know <conseal-unlock>, which offers to join or recover needs-join, or unlock-done after a recovery <conseal-join> for a join
Adding this device from another one <conseal-join> join-done The app
Approving a new device, on one that is in the circle <conseal-approve-join> approve-done or deny-done The app
Looking at their devices <conseal-devices> device-revoked The app

The elements and their properties are on the next page, and how to restyle them under Theming.

The verification-code comparison is the part of the ceremony that stops a substituted key, and these screens are where it happens: read the circle’s security page before replacing them with your own.
